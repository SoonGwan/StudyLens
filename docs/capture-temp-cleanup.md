# macOS 캡처 취소 시 임시 파일 정리

관련 이슈: #6의 캡처·취소 검증. 기존 `capture_region`은 subprocess와 파일 읽기를 기다린 뒤 PNG를 삭제하므로, future를 취소하면 삭제 코드가 실행되지 않을 수 있습니다.

작업 범위는 `src-tauri/src/platform/macos.rs`의 캡처 임시 경로·정리와 합성 subprocess 회귀 검사입니다.
권한 화면(PR #12), 코드 복사 fixture(PR #13), 실제 AI 요청·권한 변경·화면 캡처·Windows 구현과는 분리합니다.

소유한 비공개 임시 디렉터리(0700) 안에 캡처하고, future가 정상 종료·실패·취소되면 디렉터리 전체를 정리합니다.
파일만 먼저 지우는 방식은 캡처 프로세스가 늦게 파일을 새로 만드는 상황을 막지 못하므로 디렉터리 수명으로 묶습니다.

합성 데이터만 쓰는 subprocess로 정상 종료·선택 취소·빈 출력·실패·실행 실패·작업 취소 후 디렉터리 제거를 검증합니다.
실제 OS 화면 선택과 강제 종료(SIGKILL) 복구는 이 검사 범위 밖입니다.

## 검증 결과

- `bun run build:helper` 성공.
- `cargo test --manifest-path src-tauri/Cargo.toml --locked`: Rust 73개 통과(기존 67개 + 새 캡처 검사 6개).
- 합성 subprocess의 정상 종료·출력 없는 취소·빈 출력·부분 출력 후 실패·실행 실패·작업 abort를 각각 검증했습니다. 모든 경로에서 임시 디렉터리가 제거됐습니다.
- 디렉터리 권한 0700을 확인했고 실제 화면·AI·권한·사용자 클립보드는 호출하지 않았습니다.
- 작업 abort 검사는 실제 subprocess가 합성 이미지 파일을 만든 것을 확인한 뒤 task를 중단하고 파일·디렉터리 제거를 검사합니다.
- `git diff --check` 통과.

취소 시 `kill_on_drop`도 유지합니다. Drop에서 정리에 실패하면 오류를 진단 로그에 남깁니다.
프로세스 자체를 강제 종료하면 Drop이 실행되지 않으므로 그 경우의 남은 파일 정리는 보장하지 않습니다.
